# Tailor Management — Production & Smart Notification System

A complete, cloud-ready **Tailor Management & Garment Production Tracking SaaS**
for tailoring shops, boutiques and custom garment manufacturers. Manage customer
orders, assign production work across an 8-stage workflow, monitor every
garment's progress, and receive **automatic deadline reminders** — even when
nobody has the website open.

## Highlights

- **8-stage production workflow** — Bill/Order Created → Cutting → Designing →
  Embroidery → Stone/Crystals → Hand Work → Stitching → Finished. Each stage
  tracks status (Not Started / In Progress / On Hold / Completed / Skipped),
  assigned employee, planned vs actual dates, notes and history.
- **Smart days-left countdown** — timezone-aware (default `Asia/Kolkata`),
  configurable indicator bands (green/blue/yellow/orange/red badges like
  “7 Days Left”, “Only 1 Day Left!”, “Due Today”, “Overdue by 4 Days”).
- **Server-side notification engine** — scheduled deadline checks (Vercel Cron
  in production, `npm run scheduler` locally), idempotent via unique event keys
  (re-running never duplicates alerts), overdue orders get one alert per day,
  delivered/cancelled orders stop receiving reminders.
- **Polished notification UI** — stacked toast popups (max 3 + queue), critical
  alert modal with non-destructive acknowledgment, notification bell with
  unread badge and tabbed panel (All/Unread/Urgent/Production/Deadline/Overdue),
  snooze & dismiss (dismiss ≠ read), unread survives refresh/relogin, popup
  dedup across browser tabs.
- **Browser Push (Web Push + VAPID + service worker)** with per-device
  subscription management — in-app alerts keep working when push is unavailable.
- **Production Kanban board** with drag-and-drop and workflow validation.
- **Billing** — invoices with configurable tax (never hardcoded), discounts,
  advances, payment records, printable invoice + PDF download. **Currency is
  configurable per business** (INR default; USD, EUR, GBP, AED, SAR, JPY and
  13 more in Settings) — every amount, chart, export and invoice renders in
  the selected currency.
- **Optional email notifications** — when an email provider is configured
  (Resend API or any SMTP server), the daily summary and critical alerts are
  emailed (admin toggle in Settings), and users can opt in to email per
  notification category (Notifications → Notification Preferences).
- **Multi-tenant with role-based access** — Super Admin / Manager /
  Production Staff / Billing Staff, strict per-business data isolation (RLS
  policies included).
- **Customers** with measurement history, **Delivery Calendar**, **Reports**
  (on-time %, stage-wise times, revenue, CSV export), employee task dashboards,
  daily production summary at a configurable time.

### Local notification scheduler

Deadline reminders are generated by **server-side scheduled jobs**, not browser
timers. For local development run alongside the dev server:

```bash
npm run scheduler    # sweeps every SCHEDULER_INTERVAL_MINUTES (default 15)
```

You can also trigger a sweep manually: `curl http://localhost:3000/api/cron/deadline-check`

> **Note:** the local PGlite database is single-process. Run `db:*` scripts
> while the dev server is stopped (or use `DATABASE_URL` with real Postgres for
> multi-process access). Its data lives outside the project folder (default
> `%LOCALAPPDATA%/tailor-management/pglite`) so database writes never trigger
> dev-server file watching — keeping the app folder inside a OneDrive-synced
> Desktop is fine.

## Architecture

- **Next.js 16 (App Router) + TypeScript + Tailwind CSS + shadcn/ui** — UI.
- **Drizzle ORM + PostgreSQL** — one schema, two interchangeable drivers:
  - **Local/default:** [`@electric-sql/pglite`](https://pglite.dev) — real
    Postgres compiled to WASM, persisted in `.data/pglite`. No installs.
  - **Production:** set `DATABASE_URL` → node-postgres → any Postgres,
    including **Supabase**. Same migrations, same code.
- **Notification engine** (`src/server/notifications/`):
  - `engine.ts` — idempotent creation (`event_key` unique per
    tenant+order+recipient+type+delivery-date; overdue keys include the
    overdue calendar date for once-per-day recurrence).
  - `events.ts` — event-driven alerts (stage completed → next employee
    notified, task assigned/reassigned, ready-for-delivery, delivery-date
    change reschedules future reminders while preserving history).
  - `scheduler.ts` — deadline reminders (7/5/3/2/1/0/overdue with the spec's
    exact message formats), production-delay detection (not started by plan,
    exceeded duration, long holds, employee overload, at-risk orders), daily
    summary at 09:00 Asia/Kolkata (configurable), employee task reminders.
  - `push.ts` — Web Push fan-out with `notification_delivery_attempts` logging
    and expired-subscription cleanup.
- **Realtime** — SSE stream (`/api/notifications/stream`) + polling fallback.
- **Auth** — email/password with scrypt hashing and HMAC-signed HTTP-only
  session cookies; permission matrix per role (`src/lib/auth.ts`).

### Database

All 22 domain tables live in `src/db/schema.ts` (generated SQL migrations in

## Deploying with Neon Postgres (recommended)

[Neon](https://neon.com) is serverless Postgres with a free tier — ideal for
this app. The app talks to it through the standard `DATABASE_URL`, and the
built-in TLS handling covers Neon's pooled endpoints.

1. **Create a Neon project** at neon.com → *Create project* → copy the
   **Pooled connection string** (the one whose host ends in
   `-pooler.neon.tech`, format:
   `postgresql://user:password@ep-xxx-pooler…/neondb?sslmode=require`).
2. **Create the tables** — from this project folder run:
   ```bash
   DATABASE_URL="<your pooled connection string>" npm run db:migrate
   DATABASE_URL="<your pooled connection string>" npm run db:seed     # optional demo data
   ```
   (Or paste the SQL files from `src/db/migrations/` into the Neon SQL Editor.)
3. **Deploy the app** (Vercel or any Node host — see below) with these env
   vars: `DATABASE_URL`, `AUTH_SECRET`, `CRON_SECRET`, `VAPID_*` (from
   `.env.local`), optionally `EMAIL_*`/`SMTP_*`.
4. Done — orders, notifications and push all run against Neon.

Notes:
- Always use the **pooler** URL in serverless environments (Vercel).
- Neon "database branching" works nicely for staging: each branch gets its own
  connection string.

### Neon S3-compatible object storage (optional)

Neon Storage (or any S3-compatible service) holds uploaded files — logos and
order reference images — when these env vars are set:

```bash
AWS_ENDPOINT_URL_S3="https://<project>.storage.c-3.ap-southeast-1.aws.neon.tech"
AWS_ACCESS_KEY_ID=...
AWS_SECRET_ACCESS_KEY=...

# AWS_S3_BUCKET=tailor-files        # default bucket name
```

Without them, files are stored inside the database (works everywhere; see
`storage_files`). Existing files fall back gracefully: S3 → database → disk.

## Deploying to Supabase + Vercel

1. **Create a Supabase project** (free tier is fine) and copy the connection
   string into `DATABASE_URL` (use the Session pooler string for serverless).
2. **Apply migrations** — run the SQL files in `src/db/migrations/` in order
   against the Supabase SQL editor (or `psql`), or run
   `DATABASE_URL=... npm run db:migrate` locally against the project.
3. **Seed** (optional): `DATABASE_URL=... npm run db:seed`.
4. **Deploy to Vercel** with env vars: `DATABASE_URL`, `AUTH_SECRET`,
   `CRON_SECRET`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`.
5. **Cron** — `vercel.json` schedules `POST /api/cron/deadline-check` hourly;
   it authenticates with `CRON_SECRET` in production.

### Email notifications

Email is an optional delivery channel alongside in-app + push:

1. Configure the provider in **Settings → Email Setup (SMTP / Resend)** —
   choose Resend (API key) or any SMTP server (host, port, TLS, username,
   app password) and press **Send Test Email** to verify. (Env vars
   `EMAIL_PROVIDER`/`SMTP_*`/`EMAIL_API_KEY` still work and override the
   saved settings — see `.env.example`.)
2. In **Settings**, enable *"Email daily summary & critical alerts"* — the
   daily production summary and critical alerts are then emailed to their
   recipients (company rule).
3. In **Notifications → Notification Preferences**, each user can opt in to
   email per category (Deadline alerts / Production updates / Daily summary /
   Payment reminders) together with in-app and push channels.

Every email send is recorded in `notification_delivery_attempts`
(channel=`email`, status sent/failed). Without a provider, sends are skipped
gracefully and in-app alerts keep working.

### Supabase Auth / Storage / Realtime swap points

The app isolates these behind small modules so they can be swapped without
touching business logic:

| Concern          | Current implementation                    | Supabase swap |
| ---------------- | ----------------------------------------- | ------------- |
| Auth             | `src/lib/auth.ts` (scrypt + cookies)      | Replace `authenticate`/`getSession` with `supabase.auth` and keep the `SessionUser` shape |
| File uploads     | local `uploads/` directory                | Point upload routes at Supabase Storage (private bucket + signed URLs) |
| Realtime         | SSE stream + polling fallback             | Replace with a Supabase Realtime channel on `notifications` |
| Scheduled jobs   | Vercel Cron / `npm run scheduler`         | Or a Supabase scheduled Edge Function calling the same sweep |

Email/WhatsApp summaries are wired as complete provider interfaces and
activate only when their env vars are set (see `.env.example`).

## Notification behavior notes (by design)

- **No duplicate popups per alert** — DB-level dedup via `event_key`; a second
  sweep creates zero rows (verified by tests and repeat API calls).
- **Closing a toast does not mark it read** — read state only changes through
  explicit “Mark as Read”.
- **Critical alerts** require explicit acknowledgment; acknowledging never
  changes production state.
- **Delivery-date changes** recalculate future reminders; historical
  notifications are preserved and stale ones can't regenerate (their event
  keys contain the old date).
- **Delivered/cancelled orders** stop generating deadline alerts entirely.
- **Skipped stages** are excluded from progress % (completed / applicable).
