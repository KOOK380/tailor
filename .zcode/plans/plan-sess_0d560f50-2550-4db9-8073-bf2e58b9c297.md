## Notification Engine (centerpiece)

- **`src/lib/deadline.ts`** — timezone-aware calendar-day diff (`Intl` business tz → YYYY-MM-DD diff, not 24h), configurable indicator bands (spec defaults: >7 green, 7 blue, 5–6 yellow, 3–4 orange, 2 red, 1 red, 0 "Due Today", negative "Overdue by N Days").
- **`src/server/notifications/engine.ts`** — pure computation of eligible alerts per order (7/5/3/2/1/0/overdue + ready-for-delivery + task/stage/delay/summary types) with exact spec message formats. Insert with `event_key` = `tenant:order:recipient:type:deliveryDate[:overdueDate]` and `ON CONFLICT DO NOTHING` → idempotent, no duplicates on refresh; overdue → one alert per calendar day; delivered/cancelled excluded; delivery-date change recalculates future reminders, preserves history.
- **`src/server/notifications/scheduler.ts`** — the single processing entry: hourly deadline+delay checks, daily summary at configured 09:00 (Asia/Kolkata, configurable). Production trigger: **Vercel Cron** (`vercel.json`) → `POST /api/cron/deadline-check` (CRON_SECRET). Local: `npm run scheduler` (node process calls same route). Event-driven triggers (order created, stage completed, employee reassigned, delivery date changed) run inline in the same mutation transactions.
- **Delivery:** DB insert → SSE stream (`/api/notifications/stream`, polling fallback) → client popup/toaster → Web Push (`web-push` + VAPID + `public/sw.js` service worker, subscription CRUD + cleanup) → `notification_delivery_attempts` log.
- **UI:** custom toaster (white rounded cards, blue/orange/red accents, max 3 stacked + queue, snooze, dismiss ≠ read), critical-alert modal with non-destructive acknowledge, notification bell with unread badge → panel (All/Unread/Urgent/Production/Deadline/Overdue tabs, pagination), Notification Settings (admin + user), restores unread after relogin, deduped across tabs (BroadcastChannel).
